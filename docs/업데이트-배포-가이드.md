# SKY ONE SOLUTION — 업데이트·배포 가이드

코딩이 끝났다고 **sky1usa.com이 자동으로 바뀌지는 않습니다.**  
아래 순서대로 진행하면 로컬 확인 → GitHub 반영 → 실제 사이트 배포까지 할 수 있습니다.

---

## 1. 내 PC에서 미리보기 (로컬)

```bash
npm install
npm run dev
```

브라우저: http://localhost:3000

| 상황 | 동작 |
|------|------|
| 개발 서버(`npm run dev`) 실행 중 | 파일 저장 후 브라우저 **새로고침** → 대부분 바로 반영 |
| 서버가 꺼져 있음 | 위 명령으로 서버 실행 후 접속 |

→ **로컬에서만** 보입니다. sky1usa.com과는 별개입니다.

---

## 2. GitHub에 코드 반영

에이전트·본인이 수정한 내용을 저장소에 올릴 때:

```bash
git add .
git commit -m "변경 내용 설명"
git push origin <브랜치명>
```

**PR을 만들고 `main` 브랜치에 머지**하면 공식 최신 코드가 됩니다.

- 최신 홈페이지는 `main` 브랜치에 반영됨 (PR #5 머지 완료)
- PR 생성: GitHub 저장소 → Compare & pull request → 머지

---

## 3. 회사 로고만 바꿀 때

1. 채팅/메일 등에서 받은 **원본 PNG**를 PC에 저장
2. 프로젝트 폴더 안 아래 경로에 **덮어쓰기** (파일명 유지)

```
public/logo.png
```

3. Git에 반영:

```bash
git add public/logo.png
git commit -m "Update company logo"
git push
```

4. PR 머지 → (4번 배포 연결 시) 사이트에 반영

코드 수정 없이 **이 파일만** 바꿔도 헤더·히어로·푸터·파비콘이 함께 바뀝니다.  
로고 경로는 `src/lib/brand.ts`의 `LOGO_SRC`에서 관리합니다.

---

## 4. sky1usa.com (실제 사이트)에 반영

**Vercel / Netlify 등 배포를 GitHub `main`과 연결해 둔 경우**

| 단계 | 결과 |
|------|------|
| `main`에 머지·푸시 | 보통 **몇 분 안에** 자동 배포 |
| 배포 대시보드 | [Vercel — blog-starter-kit](https://vercel.com/sky-one-sol-s-projects/blog-starter-kit) → Deployments에서 **Building → Ready** 확인 |
| 수동 재배포 | 해당 Deployment → **⋯** → **Redeploy** (최신 `main` 커밋 선택) |
| 프로덕션 URL | `sky1usa.com` (또는 Vercel Production 도메인) |

**아직 배포를 연결하지 않은 경우** (최초 1회)

1. [Vercel](https://vercel.com) 등에서 GitHub 저장소 `blog-starter-kit` 연결
2. Production 브랜치: `main`
3. 도메인 `sky1usa.com` 추가 후 DNS 설정 (호스팅 안내 따름)
4. 이후부터는 `main` 머지 시 자동 업데이트

**수동 호스팅인 경우**

```bash
npm run build
npm start
```

빌드 결과를 사용 중인 서버에 직접 올립니다.

---

## 5. 전체 흐름 요약

```
코드/로고 수정
    ↓
npm run dev 로 로컬 확인
    ↓
git commit & push
    ↓
PR → main 머지
    ↓
(배포 연결됨) → sky1usa.com 자동 갱신
```
